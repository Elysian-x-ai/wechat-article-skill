# 风格 preset：效率技巧 / 清单合集

用于"一次给读者若干条可直接用上的技巧"的文章。核心价值是**密度**：每一条都要能当场用。

## 骨架

```
# 标题：N 个 <场景> 技巧 / 我做 <事> 时会用的 N 招
> 全部在 <环境/版本> 下实测。每条都标了生效条件。

## 先说结论          ← 挑 3 条最值的放前面让读者马上能用
## 1. <动作型小标题>
（2–4 行说明 + 一条命令/一步操作 + 一句"什么时候别用"）
## 2. …
## 常见坑
## 最后              ← 关键词回复 / 让读者补充他的技巧
```

## 硬性要求

- **每条独立成立**：读者跳着读也能用。所以小标题必须是**动作**（"用 `Ctrl+Shift+T` 恢复刚关的标签"），不是名词（"标签恢复功能"）。
- 每条固定三段式：**做什么 → 怎么做（可复制的操作）→ 什么时候别用**。第三段是这类文和普通搬运的分界线。
- 总条数 **5–12 条**。少于 5 条撑不起一篇，多于 12 条读者记不住，拆成系列更好。
- 顺序按**收益 × 使用频率**排，不按学习难度排。
- 「常见坑」合并所有条目里踩到的通病，不要再重复单条已说过的。
- 不配图或只配 1–2 张（如最终效果对比）。**别每条都配图**，会打断扫读。

## 语气

- 短句、动词开头、不用过渡段。
- 每条开头不要"接下来介绍"这种连接词，直接给动作。

## 反面清单

- 凑数条目（"经常保存文件"）。
- 每条都展开成长篇（那就该用 tool-review preset）。
- 只列操作不讲适用边界。
- 从别处搬运未实测的技巧 —— 版本差异会让读者当场踩坑。
