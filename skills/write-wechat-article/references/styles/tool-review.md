# 风格 preset：工具深度评测 / 完整教程

用于"把一个工具从注册到产出完整跑一遍"的文章。这类文的核心价值是**实测细节和坑**，不是功能介绍。

## 骨架

```
# 标题：提问/反差 + 我跑了一遍
> 全文约 N 字，跟着做 M 分钟能 <结果>。
> 工具：<名称>（<URL> ），<免费/付费边界>。

## 先说结论          ← 3 段内给判断：值不值、谁该用、哪个功能最被低估
## 第一步：注册登录
## 第二步：<主线动作，比如导入/新建>
### <子场景 A>
### <子场景 B>
## 第三步：<逐模块/逐功能过一遍>
## 第 N 步：<产出/导出>
## 几个提醒          ← 实测到的 bug、脾气、限制
## 最后              ← 关键词回复引导 + 适用人群回扣
```

## 硬性要求

- **按用户真实操作顺序分节**，不按功能清单。读者是"我要做成一件事"，不是"我要了解全部功能"。
- 每个大节开头**先给这一节的结论**，再讲过程。
- 至少一处**对比表格**（多方案差异、不同格式导入效果、不同选项开销）。列数 ≤4。
- 「先说结论」必须有**否定**内容：哪类人不适合、哪个功能被高估。
- 「几个提醒」≥3 条，全部来自实测，每条给出**遇到后的处置建议**。
- 结尾回扣开头的问题，给读者明确的下一步。

## 语气

- 像写完一份使用笔记后顺手发出来，不像产品宣传。
- 允许吐槽，但要给证据（我试了什么、结果是什么）。
- 每个功能都要有"这对读者意味着什么"的一句话。

## 长度分配（约 4000 字）

| 部分 | 占比 |
|---|---|
| 先说结论 | 10% |
| 走流程（分步） | 55% |
| 深度功能挑一两个细讲 | 20% |
| 几个提醒 | 10% |
| 最后 | 5% |

## 反面清单

- 逐条翻译官网功能列表 —— 读者自己能看官网。
- 只讲"怎么点"不讲"为什么这样点"。
- 所有功能都说好。
- 没跑过的功能凭描述写。
