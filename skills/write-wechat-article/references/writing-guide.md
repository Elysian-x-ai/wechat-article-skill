# 通用写作骨架（公众号）

选定风格 preset 后照此落笔。preset 管"这类文章怎么写"，本文管"公众号文章共通的规矩"。

## 骨架

```
# 标题（≤64 字）

> 全文约 N 字，跟着做 M 分钟能 <读者拿到的结果>。
> 工具：<名称>（<URL> ），<免费能做什么 / 付费能做什么>。

## 先说结论
## 第一步：<动作>        ← 按用户操作顺序，不按功能清单
### <子场景>
## …
## 几个提醒
## 最后
```

- 大节之间用 `---` 分隔（正文里渲染成分隔线）。
- 「先说结论」必须给**判断**（哪个功能最被低估、哪一环最重要、谁不适合用），不能只是目录。
- 「几个提醒」列实测到的坑，这是工具号最稀缺的内容。
- 「最后」给读者的下一步动作：关键词回复 / 关注引导 / 下一个工具预告。

## 标题

- ≤64 字（硬限制）。**不要 emoji**（订阅号标题里的 emoji 在部分入口显示异常，且显得低质）。
- 好用的两种结构：
  - **提问 + 承诺**：`简历写到怀疑人生？我把这套流程跑了一遍`
  - **反差 + 实测**：`我用了三天，把这个工具最值钱的功能找出来了`
- 不用"最/第一/绝对/震惊"，不用全角感叹号堆叠。

## 摘要

- ≤120 字。一句话说清**这篇讲什么 + 读者拿走什么**。
- 不写"点击查看""详情见下文"。留空会自动抓正文开头，但自动抓的那段通常不像摘要 —— **建议手写**。

## 排版细则

| 规则 | 原因 |
|---|---|
| 段落 **≤5 行**（手机上约 3–4 屏行） | 手机阅读，长段落直接劝退 |
| 关键结论**加粗**，但一节最多 2 处 | 到处加粗等于没加粗 |
| 小标题用 `##` / `###`，不手动造序号格式 | 结构由标签表达，平台会重写样式 |
| 列表用 `-`，步骤用 `1.`；**不用嵌套超过两层** | 手机缩进空间有限 |
| 表格仅在"对比/矩阵"时用，列数 ≤4 | 宽表在手机上会横向溢出 |
| 每 1–2 个小节配一张图，宁少勿滥 | 重复表达同一界面的图只留信息量最大的那张 |
| 代码/命令/URL 用反引号或独立成行 | 保证可复制 |
| 不写"点击这里""移至此处" | 站外链接不可点击，只能复制 |

## 口吻

- 第一人称实测视角：「我试下来」「我把它跑了一遍」。**不要**用"小编""我们"。
- 结论先行，过程其次。读者随时可能退出，每一节的开头就把这一节的结论说出来。
- 承认局限：「这个功能我没跑通」「免费版这里会有限制」比一味夸更可信。
- 不写营销套话（"赋能""闭环""一站式"），不写免责声明式废话。

## 事实核验（硬要求）

- **写之前必须亲自跑一遍并截图**。禁止凭猜测描述功能。
- 付费边界、额度、限制要**当场核对**，不能照抄官网介绍。
- 不确定就写「我这边试下来是…」，不写成绝对结论。
- 发现的 bug 如实写进「几个提醒」。
